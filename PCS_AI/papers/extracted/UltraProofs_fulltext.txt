Abstract—Reed–Solomon (RS) codes underpin a wide range of
cryptographic protocols, from verifiable secret sharing (VSS)
to blockchain data availability (DA). An RS code commitment
enables a prover to distribute codeword fragments among
many parties while allowing each recipient to verify that its
fragment is consistent with a RS code. Existing constructions
either rely on homomorphic polynomial commitments, which
incur redundant commitments and expensive group operations,
or use FRI-based interactive proofs, which achieve fast proving
but suffer from prohibitively large communication.

We present UltraProofs, a new RS code commitment
framework that achieves linear-time proof generation while
remaining compatible with any multilinear polynomial com-
mitment. Our key technical contribution is an evaluation-
consolidation protocol that reduces n evaluation proofs at dis-
tinct RS points to a single randomized evaluation, eliminating
redundant commitments and removing the need for homo-
morphic structure. We further design a tailored multilinear
PCS, LightLigero, which achieves O(λ log n) proof size and
maintains O(n log n) prover time.

UltraProofs attains asymptotically optimal prover complex-
ity with concrete speedups in practice: in VSS, it reduces
prover time by 2.4× and proof size by 4× compared to
HydraProofs (S&P’25); in DA, it cuts per-node communication
by up to 2∼5× relative to FRIDA (Crypto’24) while retaining
similar prover cost. By decoupling verifiable RS encoding from
any specific PCS instantiation, UltraProofs provides a flexible,
efficient, and modular foundation for large-scale verifiable
storage and distributed cryptographic systems.

1. Introduction

Reed–Solomon (RS) codes [1] are foundational erasure
codes that provide data integrity and redundancy in dis-
tributed storage [2], [3], secret sharing [4], [5], [6], con-
sensus [7], [8], [9], and blockchain data availability [10],
[11], [12]. Formally, an RS code RS[k, n, F] : Fk →Fn
(k < n) encodes a message vector⃗m ∈Fk into a codeword⃗

c = (f(ω0), f(ω1), . . . , f(ωn−1)),

where f(X) is the unique degree-(k −1) polynomial in-

evaluation f(ωi) is typically dispersed to a distinct user
or storage node, enabling any subset of k evaluations to
reconstruct⃗m.

In cryptographic applications [13], [14], [15], however,
the disperser may be malicious and distribute inconsistent
or invalid shares. To ensure verifiability, the notion of an RS
code commitment [15], [16] extends classical RS dispersal
with cryptographic guarantees of binding and consistency.
Intuitively, a disperser (also referred to as the prover later)
commits to⃗m and must later prove, for each share f(ωi),
that it is consistent with the committed message. This prim-
itive enables succinct, verifiable encoding of data across
many users and underpins constructions such as verifiable
secret sharing (VSS) [5], [17], [18] and blockchain data
availability (DA) [16], [19], [20].

Given that RS encoding is naturally defined by polyno-
mial evaluation, a straightforward approach to realizing an
RS code commitment is through a polynomial commitment
scheme (PCS) [21]. A PCS allows a prover to commit to
a polynomial f(X) of bounded degree such that, later, the
prover can efficiently open the commitment at any evalua-
tion point x ∈F with a short proof π, convincing a verifier
that f(x) = y. In the context of RS code commitment, the
disperser can commit to a polynomial f of degree k −1
and produces n evaluation proofs showing the evaluation
of f(ωi) for all i ∈[n]. However, this naive design is
prohibitively expensive: producing n proofs for a degree-
(k −1) polynomial requires O(kn) time.

Given the central role of RS code commitments, a
substantial line of work has sought faster proof genera-
tion procedures. A bunch of works such as AMT [22],
FK23 [23],
ZXH+22 [17] and PolyFRIM [18] achieved
O(n log n) prover time. More recently, HydraProofs [24]
attained asymptotically optimal O(n) proof generation by
introducing an OpenAll algorithm for multilinear polyno-
mial commitment within the GKR framework [25]. Con-
cretely, the prover commits to both the message⃗m and
the codeword⃗c in the form of a multilinear polynomial,
proves an FFT relation [26]⃗c = FFT(⃗m), and invokes

an OpenAll algorithm to generate proofs of⃗c[i] for the
i-th verifier. While this achieves linear-time dispersal, the
construction remains concretely inefficient: committing to
both⃗m and⃗c doubles the commitment overhead. In addition,
the OpenAll algorithm of HydraProofs [24] requires the
PCS to be homomorphic, ruling out lightweight hash-based
commitments that are often preferable in practice.

A different line of work by Hall-Andersen et al. ob-
serves the connection between RS code commitments and
interactive oracle proofs of proximity (IOPPs). Their system,
FRIDA [16], leverages the FRI protocol [27] to achieve a
very fast prover. However, FRIDA inherits the high commu-
nication overhead of FRI: each per-node proof is O(s log2 k)
in size, where s = Θ(λ) denotes a query constant typically
larger than 100 to achieve 100 bit security1. This results in
proofs of roughly 500 KB, about two orders of magnitude
larger than HydraProofs [24], rendering the scheme imprac-
tical for VSS or blockchain data-availability systems with
numerous participants.

These two directions—PCS-based (HydraProofs) and
IOPP-based (FRIDA)—highlight a fundamental trade-off in
RS code commitments. PCS-based approaches achieve low
communication cost but depend on homomorphic commit-
ments and incur redundant commitment overhead, while
IOPP-based approaches eliminate such requirements but
suffer from large communication costs. Both limitations
hinder scalable and practical deployment of verifiable data-
dispersal protocols.

In this work, we revisit the design of RS code commit-
ments from first principles, aiming to close this efficiency
gap. We ask:

Can we construct an RS code commitment that
preserves linear-time proof generation, supports
any PCS, and avoids redundant commitments?

1.1. Our Contributions

We give an affirmative answer to the above question
by presenting UltraProofs, a new framework for efficient
and flexible RS code commitments without redundant com-
mitment. UltraProofs achieves asymptotically optimal O(n)
proof generation time. It can be integrated with any mul-
tilinear polynomial commitment scheme, while removing
the need for homomorphic polynomial commitments and
substantially improving concrete communication efficiency.
Our contributions are summarized below.
• UltraProofs: a PCS-agnostic RS code commitment:
We introduce UltraProofs, the first RS code commitment
scheme that is fully compatible with any multilinear poly-
nomial commitment scheme. At its core is a new tech-
nique called evaluation consolidation, which aggregates
n evaluation proofs across RS evaluation points into a
single randomized evaluation. Unlike HydraProofs [24],

PCS can be broadly categorized into two types: group-
bas ed and hash-based schemes. Group-based schemes, such
as PST [32] and Dory [33], typically have very short
proof sizes—concretely, only a few kilobytes. However,
their prover time is usually larger, as they require O(n)
group multi-scalar multiplications during the commitment
phase.

Hash-based schemes [28], [35], [38], [39] typically rely
on error-correcting codes. These schemes use codes such as
Reed–Solomon (RS) codes to first encode the polynomial
and then construct a Merkle tree to commit to it. The verifier
can ensure that the committed vector approximates a valid

codeword by checking a constant number of randomly sam-
pled positions. Their concrete prover time is significantly
faster, as both encoding and hashing are much cheaper than
group operations. The downside is that existing hash-based
schemes incur at least O(s log n log log n) proof size [29],
where s = Θ(λ) is the number of queries, typically ranging
from tens to thousands depending on the specific error-

RS code commitment. As discussed earlier, existing RS
code commitment schemes can be broadly categorized into
two types: PCS-based and IOPP-based constructions.

Since RS encoding is defined by polynomial evaluation,
most schemes naturally build upon a polynomial commit-
ment. The high-level idea is straightforward: the disperser
commits to a degree-(k −1) polynomial f(X) using a
PCS and generates n evaluation proofs corresponding to
f(ω0), . . . , f(ωn−1). The core technical challenge for PCS-
based schemes is to generate these n proofs faster than
O(n2).

Early solutions [23] relied exclusively on the KZG
commitment scheme, which supports producing n evalua-
tion proofs in O(n log n) group exponentiation. ADVZ [9]
extended this design to the interleaved setting (dispers-
ing multiple RS codewords concurrently), achieving prover
complexity O(n log n+Ln)·G for L interleaved codewords
rather than a naive L-multiplicative cost. These KZG-based
schemes also suffer from the weakness of trusted setup.
Subsequent works such as ZXH+22 [17] and PolyFRIM [18]
generalized the approach to other PCS constructions. These
methods remove the need for O(n log n) group exponenti-
ations but still incur O(n log n) hash during proof genera-
tions, leaving the prover cost dominated by these hashing
operations.

HydraProofs [24] is the first PCS-based RS code com-
mitment achieving linear prover time. It introduces an
OpenAll algorithm [40] for multilinear PCS, enabling the si-
multaneous opening of all evaluations of multilinear polyno-
mial over boolean hypercube. However, the design relies on
a homomorphic PCS, which limits instantiations to slower,
group-based schemes. Moreover, its proof generation still
requires O(n) group operations due to the need to commit
the codeword⃗c, effectively doubling the prover’s cost.

IOPP-based solutions are proposed by Hall-Andersen et
al. in [15], and afterwards improved in FRIDA [16]. These
schemes don’t explicitly invoke a polynomial commitment
scheme, but directly commit to the entire codeword through
Merkle tree. The challenge here is how to guarantee a
single element is consistent with the entire codeword. To
circumvent this, FRIDA proves that FRI [27] can satisfy
an additional consistency criterion. The major weakness of
FRIDA is its O(s log2(nL)) proof size compared to other
schemes. This could be prohibitive when n gets larger.

2. Preliminaries

Notations. Let F denote a FFT-friendly prime field. For
a vector⃗v ∈Fn, we write v[i] for its i-th entry (indices
start from 0 by default). For a matrix M ∈Fm×n, M[i, j]
denotes the element in the i-th row and j-th column, M[i, :]
denotes the i-th row. Given two vectors⃗a,⃗b ∈Fn, we use⃗
a ⊙⃗b for their Hadamard (element-wise) product, and⃗a ⊗⃗b
for their tensor product. We denote [n] := {0, . . . , n −1}.
Given scalars v1, v2, · · · , vn, we use⃗v[:i] to denote subvector
(v1, · · · , vi).
Merkle Tree. A Merkle tree provides an authenticated
commitment to a vector by organizing its elements in a hash-
based binary tree.
• mt ←MT.Construct(⃗v): Given a vector⃗v, construct a
Merkle tree mt whose leaves correspond to the entries of⃗
v. The root of mt, denoted as mt.Root, can be treated as
the commitment to⃗v.
• (vi, pathi) ←MT.Open(i, mt): Given index i and Merkle
tree mt, it returns the i-th leaf vi together with its authen-
tication path pathi.
• rt ←MT.Recover(pathi, vi, i): Given index i, the i-th
leaf vi and its corresponding path pathi, recompute the
Merkle root of original Merkle tree. A verifier checks
whether rt = mt.Root to confirm consistency with the
commitment.

Merkle trees are typically instantiated with collision-
resistant hash functions, ensuring integrity and succinct
membership proofs.

2.3. Reed–Solomon Code Commitment

A Reed–Solomon code commitment [15] allows com-
mitting to an interleaved RS codeword c ∈RS≡L.

Definition 1 (Erasure Code Commitment). Let RS≡L :
FL×k →(FL)n. An erasure code commitment scheme CC is
a tuple (Setup, Commit, Open, Verify) of PPT algorithms:
• Setup(1λ) →gp: generate global parameters.
• Commit(gp, M) →(com, St): commit to message M ∈
FL×k, producing a commitment com and state St.
• Prove(gp, St, i) →π: produce an opening proof for
position i ∈[n].
• Verify(gp, com, i, ˆmi, π) →{0, 1}: verify that ˆmi corre-
sponds to index i of the committed codeword.

An RS code commitment must satisfy completeness,
position binding, and code binding (see Appendix A.1).
Intuitively, RS code commitments are binding vector com-
mitment with the additional property that any set of openings
is consistent with a RS codeword.

3.1. UltraProofs: Reed–Solomon Code Commit-

UltraProofs eliminates the redundant polynomial com-
mitment present in prior RS code commitments while pre-
serving linear-time proof generation. Our construction builds
on the structural connection between RS codes and polyno-
mials. As discussed in Section 2.4, a natural baseline is to

a univariate PCS: the prover commits to a degree-(k −1)

Evaluation consolidation: many fixed to single random.
To achieve efficient multi-evaluation, we extend evaluation
reduction to handle many points concurrently. The key
observation is that if all reductions share the same verifier
randomness⃗r, then after each round of reduction, the num-
ber of distinct evaluation claims halves. For example, for
evaluation points (ωi, ω2i, . . .) and (ωi+n/2, ω2i, . . .), the
two claims merge after the first randomization step since
they differ only in the first variable. Thus, after µ rounds,
all claims consolidate into the single point⃗r.

To ensure a shared random challenge across all concur-
rent reductions, we employ a modified Fiat–Shamir transfor-
mation following [17]. In each round, the prover constructs
a Merkle tree over all per-instance randomness and derives
the shared challenge from the Merkle root. Each verifier
is provided with its corresponding Merkle path as proof of
correct challenge derivation. Because the number of distinct
messages halves per round, the total hashing cost of this
procedure is O(n). The proof size is O(log2 n), as there are
log n rounds, and each round includes a Merkle path with
an amortized length of O(log n).
Reducing communication overhead. We further reduce
round complexity—and thus communication—by batch-
ing variable randomization. Instead of randomizing a sin-
gle variable per round, the prover can send an s-variate
polynomial ˜li(X1, . . . , Xs), thereby randomizing s > 1
variables at once. This reduces the number of rounds
from µ to µ/s while slightly increasing soundness error
from µ/|F| to (µ/s) · (2s/|F|), which remains negligi-
ble for s = O(log log n). The total proof size becomes
O(log2 n/ log log n).

3.2. LightLigero: Multilinear PCS with O(λ log n)
Proof Size

A multilinear PCS is a critical component of Ultra-
Proofs. Existing PCS schemes impose significant overhead
in either computation or communication. We design a new
PCS optimized for the cost profile required in interleaved
RS code commitment, especially data-availability (DA) ap-
plications.

Polynomial commitment schemes can be roughly di-
vided into two categories: group-based and code-based.
Group-based PCS (e.g., PST [32], Dory [33]) achieve com-
pact proofs but require expensive multi-scalar multiplica-
tions (MSM). Code-based PCS (e.g., Deepfold [28]) rely
on Merkle-tree commitments, offering fast prover time at
the cost of larger proof size: committing to O(log n) trees,
each opening Θ(λ) paths, yields O(λ log2 n) proof size. For
example, for a polynomial of size 220, PST produces a ∼1
KB proof in ∼7 s, whereas Deepfold achieves ∼2 s prover
time with a 300 KB proof (assuming code rate 1/4).

Our PCS combines the advantages of both approaches.
Inspired by Ligero++ [35], the prover commits to the multi-
linear polynomial ˜f via an interleaved RS code. Specifically,
the polynomial coefficients are arranged into a log n ×
(n/ log n) matrix C, which is encoded under RS≡log n. Each
column of C is committed as a leaf in a Merkle tree,
forming the public commitment. Let µ′ = log log n. During
evaluation at (z1, . . . , zµ), the prover commits to the reduced
(µ −µ′)-variate polynomial

˜f ′(Xµ′+1, . . . , Xµ) := ˜f(z1, . . . , zµ′, Xµ′+1, . . . , Xµ)

using a group-based PCS (e.g., Dory [33]) and proves its
evaluation ˜f ′(zµ′+1, . . . , zµ). The central challenge is to
prove consistency between the RS-code-committed polyno-
mial ˜f and the group-committed ˜f ′.

We ensure consistency by sampling λ random columns
from the interleaved RS code and performing batch evalu-
ations of ˜f ′ at λ corresponding points. The overall prover
time, including both commitment and evaluation, is

6. Applications

We highlight three representative applications of Ul-
traProofs: verifiable secret sharing (VSS), blockchain data
availability (DA), and multi-verifier zkSNARKs. All three
rely on a common capability—dispersing encoded data
among many participants while providing succinct, locally
verifiable proofs of correctness for each share.

6.1. Verifiable Secret Sharing

Secret sharing enables a dealer to distribute a secret
among n participants such that any subset of at least k
participants can reconstruct the secret, while smaller subsets
learn nothing. Typically, n is set to 2k to achieve opti-
mal fault tolerance in synchronous Byzantine settings. A
verifiable secret sharing (VSS) protocol additionally guar-
antees verifiability: even if the dealer is malicious, honest

UltraProofs integrates naturally as a commitment prim-
itive for VSS, offering both succinct proofs and linear-time
encoding. To additionally guarantee privacy against coali-
tions of fewer than k participants, we extend the committed
object to include a random masking polynomial.

Concretely, the dealer constructs a single multilinear
polynomial ˜h that jointly encodes two k-length components:

˜h(Y,⃗X) = ˜f(⃗X) + Y · ˜g(⃗X),

where ˜f represents the secret polynomial and ˜g is a random
masking polynomial sampled uniformly from the same func-
tion space. The dealer commits once to ˜h using multilinear
PCS, obtaining the commitment comh.

To distribute shares, the dealer derives a random scalar
β ∈F (via Fiat–Shamir or a public coin) and, for each
participant i, sends:
1) the actual secret share ˜f(ωi),
2) the masked evaluation ˜g(ωi),
3) an opening proof that ˜h(ωi, β) is consistent with comh.
Opening proofs in the third part only transmit evalua-
tions of ˜f(ωi) + β˜g(ωi). Since ˜g is uniformly random, the
linear combination ˜f + β˜g is statistically independent of ˜f.
Even if adversaries obtain the entire polynomial ˜f + β˜g,
perfect secrecy of ˜f is still preserved.

6.3. Multi-Verifier zkSNARKs

The evaluation consolidation technique of UltraProofs
can also be applied to multi-party verification, where mul-
tiple verifiers each hold distinct pieces of input data con-
tributing to a common computation.

Consider a setting with a single prover P holding the
vector⃗x = (x1, . . . , xn) and n verifiers {V1, . . . , Vn}, where
each Vj possesses its local input xj. The prover wishes to
convince all verifiers that there exists a witness⃗w satisfying
a relation

C(⃗x,⃗w) = 1,

while also ensuring that each verifier’s local input xj is
correctly embedded in the committed vector⃗x. To do so,
the prover must generate:
1) n proofs showing that each verifier’s input xj corre-
sponds to the j-th segment of the committed vector
comx, and
2) a zkSNARK proof attesting that C(⃗x,⃗w) = 1 and that⃗x
is consistent with comx.

Let ˜f denote the multilinear extension of⃗x over µ
variables. Our evaluation-consolidation protocol can reduce
all 2µ point evaluations of ˜f at {0, 1}µ—corresponding to
the local inputs held by 2µ verifiers—into a single evaluation

˜f(⃗r) at a common random point⃗r ∈Fµ, along with 2µ
succinct reduction proofs. In the i-th round, the prover
sends the message ˜f(⃗r[:i−1], X,⃗b[i+1:]) to all verifiers whose
indices share the suffix⃗b[i+1:]. This structure enables all
verifiers to share the same verifier randomness while main-
taining soundness. Since many modern zkSNARK construc-
tions [50] use multilinear PCS commitments to represent
circuit wire values, UltraProofs can be seamlessly integrated
into existing zkSNARK frameworks with negligible addi-
tional cost.

7.2. Data Availability

We next evaluate the combination of UltraProofs and
LightLigero in a data-availability setting, which corresponds
to the interleaved RS code commitment scenario.
Parameter choice. Industrial DA systems such as Celes-
tia [58] and EigenDA [59] currently support block sizes of
around 15MB. To reflect near-future scalability targets, we
evaluate block sizes ranging from 32MB to 128MB. Given
that a scalar field element of BN254 can approximately
encode 32 bytes of information, this block size range cor-
responds to polynomials of length (i.e. k × L in the context
of interleaved RS code) 220 to 222. To emulate realistic
decentralization6, we vary the number of DA nodes N from
1024 to 4096, which corresponds to the number of inter-
leaved RS codeword columns n ranging from 210 to 212.
The code rate is fixed at ρ = 1/4, consistent with common
DA security settings [16], [48]. We measure the cost of RS
code commitments under these DA configurations.

Table 3 reports concrete performance of FRIDA and
UltraProofs. When paired with our custom PCS LightLigero,
UltraProofs achieves a 2∼5× reduction in per-node commu-
nication compared to FRIDA, with only a ≤25% increase
in prover time. For UltraProofs+Dory, communication drops
by roughly 6× relative to FRIDA, albeit at a 3× slower
prover. The two instantiations thus reflect a tunable trade-
off between proof size and prover complexity, governed by
the choice of underlying PCS. In all settings, verifier time
remains under 50ms.

The trade-off of slightly increasing prover time for
reduced communication is advantageous in DA, not only
from a numerical perspective, but also because per-node
communication is inherently more critical than prover time.
Specifically, per-node communication imposes a bandwidth
constraint on each DA client, whereas the prover cost is
borne solely by the disperser. Since the primary goal of
DA is to enable participation in blockchain consensus by
more resource-constrained clients, lowering bandwidth re-
quirements is more crucial than minimizing prover time.

7.3. Multilinear Polynomial Commitment

Finally, we implement our multilinear PCS, LightLigero,
by integrating it with PST [32], and compare it with
Deepfold [28] and WHIR [29]. All three are RS-code-based
constructions with similar asymptotic prover complexity. We
ranges the polynomial size from 219 to 224, covering block
size currently and in the near future. The code rate is fixed
at 1/4.

As shown in Figure 2, the prover time of LightLigero
is about 30% slower than Deepfold due to the inclusion of
additional multi-scalar multiplications, yet it remains 1.8×
faster than WHIR, whose evaluation step involves heavy
IFFT/FFT operations. In terms of proof size, LightLigero
achieves 4× compression relative to Deepfold and 2× rela-
tive to WHIR, owing to its asymptotically smaller O(λ log n)
bound. For a polynomial of size 221 (64 MB of data),
Deepfold produces 225 KB proofs, WHIR 104 KB, and
LightLigero only 54 KB. The verifier time of LightLigero
is roughly 3× and 11× longer than that of Deepfold and
WHIR, respectively. However, since all of them are below
10 ms, this will not become a system bottleneck in Ultra-
Proofs’s target applications.

8. Conclusion

In this work, we presented UltraProofs, a framework
for scalable and PCS-agnostic Reed–Solomon code com-
mitments. By introducing a non-interactive evaluation con-
solidation protocol, UltraProofs avoids redundant codeword
commitments and removes the reliance on homomorphic
PCS backends, achieving asymptotically optimal O(n) proof
generation while remaining compatible with any multilinear
PCS. To improve concrete efficiency, we further devel-
oped LightLigero, an RS code-based multilinear PCS that
achieves O(λ log n) proof size with O(n log n) prover time,
reducing communication overhead relative to prior hash-
based designs.

We evaluated UltraProofs in the contexts of verifiable
secret sharing and blockchain data availability. In VSS,
UltraProofs achieves a 2.4× reduction in prover time and
a 4× reduction in proof size compared to HydraProofs
(S&P’25). In DA, UltraProofs combined with LightLigero
reduces per-node communication by 2∼5× compared to
FRIDA (Crypto’24).

These results indicate that UltraProofs provides a prac-
tical and modular foundation for large-scale verifiable data
dispersal, while maintaining compatibility with a broad class
of polynomial commitment schemes.

Appendix E.
Meta-Review

The following meta-review was prepared by the program
committee for the 2026 IEEE Symposium on Security and
Privacy (S&P) as part of the review process as detailed in
the call for papers.

E.1. Summary

This work presents efficient (batched) Reed-Solomon
(RS)
code
commitments,
which
are
commitments
to
(batches of) RS codes such that later any set of indices
of the code can be proven with respect to the commitment.
Such commitments are building blocks for VSS schemes
and data-availability schemes.

It proposes a new RS code commitment scheme, Ultra-
Proofs. UltraProofs works by batching multiple polynomial
evaluation checks into a single evaluation check, and lifts
this efficiently to proving multiple evaluations of multiple
RS codes.

This work additionally designs a new polynomial com-
mitment scheme, LightLigero, for proving the final batched
polynomial evaluation claim efficiently. Finally, the paper
benchmarks both LightLigero individually as well as Ultra-
Proofs in the context of VSS and data availability.

E.2. Scientific Contributions

• Creates a New Tool to Enable Future Science.
• Provides a Valuable Step Forward in an Established Field.

E.3. Reasons for Acceptance

1) The paper proposes a new batching scheme for mul-
tivariate polynomials, a new polynomial commitment
scheme, and a way to lift this to RS code commitments.
Additionally, the paper shows how to apply these to two
applications of general interest (VSS and DAS).
2) The core result of compressing polynomial evaluation
claims is new and general enough to be potentially useful
in other contexts as well.
